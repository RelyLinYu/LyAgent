# LyAgent mechanical artifact acceptance

[English](README.md) | 中文

## 概述

可选 host 规则在最终交付观察者记录 `deliverables/presented` 前，检查原生 `present` 工具结果。每个配置要求的产物必须已声明，在读取期间保持同一提供方版本的普通文件，满足显式正数字节范围与必需字面文本，并匹配可选的原始字节 SHA-256。规则来自部署配置，不能由模型提供成功标准。每次交付都重新运行全部规则；文件改变后不复用旧成功。

## 使用此包

在任务专用 overlay 中配置 `artifacts: [{ path, minBytes, maxBytes, includes, sha256? }]`。通用编排 overlay 不附带规则或自动批准。路径通过原生文件提供方依据当前 Session 目录解析。原生权限与父子工具策略继续生效。检查失败以 `LYAGENT_ARTIFACT_REJECTED` 阻止交付；提供方失败同样拒绝工具。成功结果在模型可见日志中包含已检查原始字节摘要。不配置 `tests` 时不执行 shell。可选测试使用原生 PowerShell；两种模式都不启动额外模型请求。

可选 `tests` 要求 `{ python, root, files: [{ path, sha256 }], minTests, timeoutMs }`。Python 和评测根目录必须为绝对路径，评测根目录须在工作区外，平级 `.py` 文件名固定原始字节 SHA-256。已验证源字节直接编译，不从字节码缓存导入。原生 `pwsh` 策略、批准与取消保持生效。每次调用到期终止，不转为后台。交付要求完整前台结果、退出零、完整 JSON stdout、达到正数最小测试量，且没有超时、取消、沙箱拒绝、失败、错误或跳过。测试后再次检查产物版本。外层交付日志保留测试摘要；内部执行器调用不创建模型步骤。

### 任务执行与修复

多个产物映射指向同一工单时，修复只选择与持久化 host 拒绝路径匹配的映射，不使用另一产物的工作者策略。没有持久化拒绝且存在多个匹配映射时，以歧义停止，不选择首个路由。

候选的可选正数 `maxActive` 限制同一产物映射和任务运行时实例内的活动修复激活数。不配置则不施加候选专属上限。选择排除满载候选，在异步启动前同步预留选定身份，并仅在成功释放激活后于成功、失败或取消路径释放预留。释放失败时保留预留与只读 guard，直到运行时拆除，因为子任务静止尚未确认。满载映射停止，不排队或重试。这些进程内预留不跨映射、服务或重启共享，也不替代持久化模型预算准入。

修复映射可用有序 `candidates: [{ id, enabled, capabilities, provider, model, readOnlyTools }]` 与 `requiredCapabilities` 替代 `worker`。只有 host 授权路由参与。派发前记录禁用候选、缺少声明能力及未注册提供方，再选择首个合格项并将其他合格项记为低优先级。能力标签是可信声明，不代表测得的能力。选择不探测提供方；精确模型或执行失败会停止，不尝试其他候选。决策记录到子任务输入和父任务建议。这是有界修复路由选择，不是通用容量调度，也不替代原生模型工具 Session 授权。

Web 任务运行时验收在 `apps/web/tests/expected/lyagent-task-recorded-session.jsonl` 保存完整归一化原生 Session 输出基准。它通过真实任务执行、文件工具与独立 Python 评测重放已提交 artifact-gate 模型流，随后比较所有归一化事件。精确临时路径、Web origin 和共享时间上下文归一化去除每次运行值；工具结果、摘要与事件顺序保留。这是无密钥输出基准，不是新的付费录制或规范 Session 重放代次。

最终产物复核在读取前拒绝超过已注册部署与附加要求字节上限的文件。最终产物或评测读取中的带类型文件系统失败使验收保持未确认，并将任务结算为需关注；不会完成任务或安排修复。意外实现失败仍向上传播。

任务结算在既有关注原因中持久化全部检测到的失败：缺失交付、未确认产物或评测版本、知识授权改变、预算未结算、批准或工具记录不完整、工单未完成、子任务证据和更新的会话工作。这些诊断不授权重试，也不证明未知外部效果安全。历史记录保留原有原因。

可选 `repairTargets: [{ path, workOrder }]` 将唯一配置产物路径固定到原生工单身份。人工 `/task coordinate <id>` 显式执行，只有在轮次完整结束，工具、批准、子任务、来源及预算均已结算后，才可重新打开失败产物映射工单及其依赖后代。修复还要求同一工单服务、状态可读、全部注册工单仍在，以及此前修复中已完成独立分支不变；轮次中删除工单会阻止自动纠正。每次纠正先持久化预留修复额度，再修改，且要求新原生轮次与全新独立验收。未知效果、预算失败、无映射路径、取消及仅评测失败均停止而不重试。`/task run` 仍是单次执行。协调器不从模型文本推断工单身份，也不约束文件写入；可信部署映射必须对应预期工单。通用预览未启用映射或自动修复。

任务所属的声明、缺文件、字节范围与必需文本等机械失败会持久化配置产物路径、host 诊断和所属轮次序号。显式修复执行在新尝试清除当前拒绝前，把此前路径与诊断和受影响工单一起复制到下一条用户输入日志。独立验收成功也会清除拒绝。迟到或其他尝试不能替换它。记录本身不启动修复或模型请求。没有拒绝字段的历史任务保持原义。

修复映射还可配置 `worker: { provider, model, readOnlyTools }`。省略时保持仅父执行。配置路由会在修复父任务首次请求前启动一个原生 `spawn` 激活；目标、重新打开的工单和此前 host 拒绝记录到子任务。临时单调执行 guard 将该根任务的后代限制在可信只读工具列表内，直到激活释放。工具名是 host 审计策略，不代表推断出的安全。完成的子输出连同身份包装必须符合 `tests.maxChildResultBytes`，之后才作为未验证建议追加到父任务日志。未完成、取消或输出超限会停止该尝试而不重试；独立产物、子输出与预算检查仍决定结算。这是固定部署路由，不是通用工作者选择或文件系统隔离。

人工 `/task define {"objective":"...","requirements":[{"path":"report.md","minBytes":1,"maxBytes":4096,"includes":["Required text"]}]}` 在部署规则上添加不可变产物要求。路径为有界相对路径，不得穿越父目录；要求不含可执行评测输入。每次交付检查两组规则，每个产物摘要只记录一次。附加大小不得超过部署最大产物上限。任务执行输入日志包含这些公开要求。没有可选 `requirements` 的历史任务不增加检查。此入口不替换可信独立测试配置，也不授权文件访问。

`/task criteria` 无模型调用地读取当前部署的必需产物路径、正数字节范围、最小独立测试量和纠正上限。不暴露隐藏评测文件名、路径、源码或必需字面答案。这是只读摘要，不是验收规则编辑器。

新任务注册固定完整可信产物规则、评测配置和纠正上限的 SHA-256。新尝试会拒绝改变后的部署标准，要求重新注册任务。没有此可选摘要的历史任务保留此前未固定含义。摘要不暴露隐藏评测源码，也不允许模型提供标准。

显式修复在重新打开受影响工单前，固定已完成独立工单身份与修订号。结算要求这些工单仍在同一修订且已完成，即使后续交付捕获了编辑后的工单。没有可选固定记录的历史修复保持原义。这些固定记录不约束工作区文件写入。

`/task repair <task-id> <work-order-id>` 显式重新打开已完成但失败的工单及其传递依赖后代，不启动模型请求。所属任务必须需关注，根会话必须 idle。每次修复先持久化预留一次额度，再执行原生 compare-and-set 工单更新；预留及每次工单追加前检查取消。部分失败或取消保留额度与已提交工单改变，不重试。独立分支保留修订。同一个配置 `maxRepairs` 对每任务显式修复预留提供上限，与交付检查分别计数。后续 `/task run` 在日志中说明受影响身份，要求模型保留无关已完成工作与产物，然后必须重新独立验收。此指令不是文件系统写入约束。修复不自动选择失败工单或派发替补子任务。

任务评测器接收 `LYAGENT_CHILD_RESULTS`，其中包含 host 读取的本地子输出、Session 身份与 SHA-256。有子任务时，`tests.maxChildResultBytes` 必须显式约束完整序列化列表。pending 子任务、无最终输出、不完整日志和输入超限会在评测前阻止交付。结算重读相同激活输出，拒绝改变的测量。测试必须显式断言任务专属子内容；收到输入本身不确立语义正确性。此机制不自动安排依赖驱动修复。

`/task list [after]` 仅返回当前会话任务身份、状态和裁剪至 240 字符的目标。每页最多五十项；用返回的 `next` 继续。目录不暴露产物或评测路径，不触发执行。host `list(agent, after)` 使用相同持久化记录与隔离。

任务组合要求显式零至二的 `maxRepairs` 整数。每次尝试允许首次交付检查及最多该数量后续修复检查；再交付会先清除旧验收并取消所属原生轮次。此限制约束交付验证，不约束通用模型步骤或任意编辑；运行计量独立限制请求与 token。host 重启不将活动尝试自动恢复执行。

同时挂载 `taskRuns` 与原生命令注册表时，`/task new <objective>` 注册未启动任务并返回身份。`/task status <id>` 读取当前会话任务；`/task run <id>` 显式执行排队或需关注任务，要求已挂载运行预算，不自动重试，等待根与子工作并最终结算。`/task cancel <id>` 记录取消，并只对该任务活动尝试请求原生停止。注册和状态读取不发起模型请求。命令拒绝跨会话身份及会话并发或排队工作；任务产物与评测标准来自可信部署。取消命令请求会通知原生停止，但 host 执行继续拥有清理责任，直到轮次结算。


可选 `taskRuns: true` 还要求原生 agents、会话持久化、storage-domain 服务与独立测试。host API `ctx.lyagentTaskRuns` 注册显式目标，在开放原生轮次绑定尝试，读取持久化状态、取消并在轮次后显式结算。`present` 成功仅记录待定验收。结算刷新并独立打开原生持久化历史，要求匹配交付及轮次结束，再次计算产物和评测摘要。仅 idle 不能完成任务。插件启动时把中断尝试变为 `needs_attention`，从不重放。可移植命令支持人工附加要求与显式映射的有界协调，不提供可信评测编辑器或通用失败诊断。



独立测试失败会区分执行不可用或被拒绝、到期、中断、退出失败、进程字段不完整、沙箱拒绝、JSON 输出不完整及测试数量不达标。诊断不暴露评测原始 stdout/stderr，也不声称未确认进程通过。

成功测试摘要包含每个固定评测文件名、SHA-256 和测试数量；外层持久化工具结果将评测输入与已检查产物摘要绑定。

启用任务运行时，每次后续交付会清除此前 pending 候选。任务完成还要求所属轮次最后工具调用是该已接受 `present`，持久化工具结果成功，没有更新的原生轮次，且持久化任务修订不变。之后再调用工具，保守要求重新交付检查。

所属轮次的持久化批准审计必须为每个请求包含一个匹配决策。未回答请求、重复开放身份及无匹配决策阻止完成。已关闭拒绝本身不否定后续独立验收交付。

所属轮次每个工具调用必须恰有一个结果；缺失结果、重复开放调用身份、无匹配结果及原生 `TOOL_OUTCOME_UNKNOWN` 阻止完成。普通已关闭工具失败本身不否定后续独立测试交付。此审计覆盖已记录调用，不覆盖隐瞒或脱离的外部效果。

原生子生命周期跟踪要求任务根下每个观察到的激活在完成前释放资源。idle 但仍驻留的子任务仍阻止结算；尝试期间子任务异常结束同样阻止。移除或替换 subagent 服务阻止完成。此机制不独立验证子建议结果。

尝试开始时挂载原生 Team 服务，则结算要求同一底层服务实例，且全部当前未删除工单已完成。验收捕获各工单身份和修订；结算要求完全相同列表，因此后续编辑、依赖改变或新增要求重新交付。注册保存当前工单身份，结算时必须仍存在并完成。所属轮次删除工单也阻止完成。状态来自原生同步投影，含 Team 模式禁用时。此保守检查覆盖整板，不确立每个子结果的独立验收，也不自动调度局部修复。

注册任务时若挂载知识服务，任务保存该会话已授权版本及来源文本摘要的完整 host 清单。结算要求同一清单；撤销或替换授权不能让任务以旧来源完成。若服务不存在，注册不保存知识要求。缺少可选字段的历史任务保持原义。此机制绑定来源输入，不保证引用语义支持或模型读过每项来源。

尝试开始时捕获已挂载预算服务。结算要求同一服务，根轮次配额已封存，全部批次用量在批次、运行和成员限额内结算。未跟踪、pending、未知或超限用量阻止完成。尝试期间移除、替换或新增预算服务也阻止完成。若全程没有预算服务，此 API 不验证预算；生产付费任务组合必须显式挂载运行计量。

<a id="model-experience"></a>
## 模型体验

### 交付检查

#### 模型看到的内容

检查失败返回 `Artifact acceptance failed:` 与未满足的机械要求。成功调用追加 `Mechanical artifact checks passed for these versions only:`、已检查路径和 SHA-256。

#### Token 影响

每次交付按条件增加结果文本。配置工作者的显式协调修复会启动原生子激活，计入所属根轮次预算；无映射则不启动工作者。

#### KV Cache 影响

工具结果只追加；现有请求历史不变。

<a id="known-limitations-and-deferred-work"></a>
## 已知限制与暂缓工作

- 文件规则检查字面文本、大小与摘要。可选测试只确立可信测试断言的事实，不保证通用语义正确或来源蕴含。交付通过不等于任务完整验收。
- 原生 `present` 打开当前文件而不是不可变副本。报告摘要仅绑定已检查版本；后续变更需新检查，并可能改变用户打开的内容。
- 此机制约束 `present`，不约束任意助手完成声明、shell 副作用或全部工作区文件。可选任务运行要求显式 host 编排，不将子工单内容绑定到独立语义证据。结算独立重开每个已观察本地子任务的持久化激活后缀，要求完成且关闭的轮次、成对工具调用结果且无未知效果、已关闭批准对。外部子任务若没有可读本地历史不能通过。审计不调和未记录外部效果，也不校验子文本含义。评测是可信可执行代码，不是 OS 隔离的对抗评委；评测目录与 Python 安装须由 host 控制。
- 检查在进程内依据文件提供方新鲜度保证运行，不提供针对高权限并发写入者的 OS 约束。部署代码必须可信。
