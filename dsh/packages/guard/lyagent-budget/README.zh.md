# LyAgent authorization batch policy

[English](README.md) | 中文

## 概述

可选策略通过已配置的 storage-domain 后端控制原生 `llm/stream` 准入。配置显式 `batchId`、不可变的 `maxRequests` 和 `maxTokens`、保守的 `reservationTokens`，以及一至三的 `maxConcurrent`。部署 overlay 不附带活动授权。

<a id="use-this-package"></a>
## 使用此包

每次提供方流在派发前持久化预留一次请求和 token。仅成功终止的流可用权威输入输出总用量替换预留。缺失、格式错误、失败或中断的用量保留为未知预留，并阻止后续调用。重启后发现的 pending 记录同样阻止请求。同一批次身份下修改限额会失败。记录只含计量，不含凭据或请求内容。

存储的请求身份必须唯一，token 计数与聚合总量必须保持安全整数。无效计量阻止激活。结算缺失的预留会失败，不会报告计量成功。

策略覆盖同一 host 内的辅助与子任务模型请求。并发饱和时在派发前拒绝，不排队、不重试。有界验收应禁用原生自动重试。存储失败向上传播并停止操作，不会报告预算结算成功。

可选 `runLimits` 显式提供 `maxRequests`、`maxTokens`、`childMaxRequests`、`childMaxTokens`。每次准入在同一批次记录内保存根 Session、原始轮次起始序号和成员 Session id。父运行与成员检查在批次持久化预留中完成。子任务在激活发布时捕获所属运行；父轮次前进不会把活动子任务费用移到新运行。运行或成员已使用的限额不能改变。

启用运行限额后，每个流必须有活动的原生所属 Session，以及开放根轮次或已捕获的子配额。缺少所属关系时在派发前拒绝，包括无主辅助调用。仅批次部署保留原有行为。

仅 host 可用的 `ctx.lyagentBudget.seal(run)` 持久化关闭一个根 Session 与轮次起始序号的准入。仅当该运行有已跟踪请求、所有批次请求均已结算且批次、运行、成员实际用量均在限额内，才返回计费数量与 `ready`。pending、未知、未跟踪或超限用量不能完成业务任务。封存幂等，迟到的权威结算仍可写入，但根与子请求不能再准入。仅批次计量不能确立任务就绪。

<a id="known-limitations-and-deferred-work"></a>
## 已知限制与暂缓工作

- 运行限额约束根轮次，不是独立持久化业务任务实体。子配额是统一配置的上限，不保证每个子任务都获得容量。
- 子任务所属运行只保存在进程内。重启或插件重载后，子任务需要在开放父轮次下重新发布激活；不会自动重新绑定或恢复执行。持久化请求配额继续计费。
- 预留是保守准入计量，不是提供方强制账单上限。提供方可能报告超过预留的用量；全部用量会保留并阻止之后的准入。
- 未知用量需要显式外部复核，不会自动清除或扩大批次。
- 生产部署保持显式启用，直到真实组合与取消生命周期验收通过。
